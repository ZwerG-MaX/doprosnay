# Допросная №2 — пульт наблюдения (Ростелеком · Видеонаблюдение)

Web-пульт для комнаты наблюдения при допросной: видеостена **MACROSCOP** (3 камеры на комнату),
аудиоканал **Mumble** с тангентой (PTT), совместный протокол в **ONLYOFFICE Docs**,
ролевая модель (пользователь / администратор), распределение по комнатам и правам.

Стек: React 18 + TypeScript + Vite 6 + Tailwind CSS 4.

---

## Быстрый старт (демо-режим)

```bash
npm install
npm run dev          # http://localhost:5173
```

Продакшен-сборка и локальный запуск сборки:

```bash
npm run build        # → dist/
npx vite preview     # http://localhost:4173
```

В демо-режиме всё работает из коробки: видеопотоки и аудио эмулируются,
ONLYOFFICE при недоступном сервере переключается во встроенный редактор,
права и настройки хранятся в localStorage.

---

## Запуск с реальными серверами

Весь реальный стек поднимается одной командой (нужны Docker и Docker Compose):

```bash
docker compose up -d
```

Поднимутся: **ONLYOFFICE Document Server** (`:8080`), **Mumble/Murmur** (`:64738`),
**MediaMTX** (медиапрокси MACROSCOP, `:8888`/`:8889`) и **nginx** с хранилищем документов (`:8090`).

Затем войдите в пульт **администратором** → кнопка **«СЕРВЕРЫ»** в шапке → внесите адреса
и нажмите «ПРОВЕРИТЬ» (для ONLYOFFICE выполняется реальная проверка `api.js`).

### 1. ONLYOFFICE Docs — поддерживается полностью

После `docker compose up -d`:

1. Положите документ в `infra/docs/`, например `protokol-doprosa.docx`.
2. Проверьте, что он отдаётся: `http://localhost:8090/protokol-doprosa.docx`.
3. В панели «Серверы → ONLYOFFICE Docs» укажите:
   - **Адрес Document Server**: `http://localhost:8080`
   - **URL документа**: `http://docs/protokol-doprosa.docx`
     ⚠️ Документ скачивает **сам Document Server из своего контейнера** — поэтому
     `localhost:8090` не подойдёт. Используйте имя сервиса compose (`docs`) или
     адрес, доступный из контейнерной сети (`host.docker.internal:8090` на Docker Desktop).
   - **JWT-секрет**: в `docker-compose.yml` по умолчанию `JWT_ENABLED=false` (быстрый старт).
     В проде включите JWT и впишите тот же секрет в это поле. В реальной эксплуатации
     токен должен подписываться вашим бэкендом (сейчас передаётся статически).
4. Нажмите «ПРОВЕРИТЬ ДОСТУП» и «ПРИМЕНИТЬ» — панель протокола подключит настоящий
   `DocsAPI.DocEditor` с совместным редактированием в реальном времени.

> Полноценное сохранение версий (`callbackUrl`) требует небольшого серверного обработчика
> (endpoint, принимающий POST от Document Server и кладущий файл в хранилище).

### 2. Mumble — сервер реальный, аудио в браузере через мост

Murmur поднимется на `64738/udp` (пароль суперпользователя Murmur печатает в лог при первом старте).

Браузер не говорит по нативному протоколу Mumble, поэтому для реального звука нужен мост:

- **[mumble-web](https://github.com/Rantanen/mumble-web)** + `mumble-web-proxy` (WebSocket ⇄ Mumble).

Точка подключения в коде — `src/lib/usePtt.ts`: вместо эмуляции (WebAudio-сигнал,
таймер передачи) подключается коннектор mumble-web (`MumbleConnector`), а состояние
`tx/muted/deafened` связывается с реальным каналом. Адреса сервера уже редактируются
админом в панели «Серверы → Mumble».

### 3. MACROSCOP — видео в браузере через медиапрокси

MACROSCOP отдаёт камеры по RTSP, а браузер RTSP не играет. Связка:

```
MACROSCOP VMS (RTSP) ──► MediaMTX ──► WebRTC/HLS ──► <video> в пульте
```

1. В `infra/mediamtx.yml` пропишите RTSP-адреса ваших камер VMS (поле `source` у `cam01…cam03`).
2. Проверьте поток: откройте `http://localhost:8889/cam01` (WebRTC-превью MediaMTX).
3. Точка подключения в коде — `src/components/CameraFeed.tsx`: замените `<img>`
   (демо-кадр) на `<video>` + WebRTC через WHEP API MediaMTX
   (`POST http://localhost:8888/cam01/whep`). Остальное (HUD, таймкод, REC, снимки)
   продолжит работать поверх видео.
4. Адреса VMS (хост/порт/протокол) админ правит в панели «Серверы → MACROSCOP» —
   из них собираются RTSP-URI камер и строка подключения.

## Роли и права

- **Пользователь** — смотрит только назначенные комнаты; протокол в режиме чтения,
  если админ не выдал право редактирования (в ONLYOFFICE передаётся `mode: "view"`).
- **Администратор** — все комнаты, панель **«СЕРВЕРЫ»** (адреса, порты, JWT,
  включение/отключение каждого подключения, диагностика) и **«ДОСТУП»**
  (матрица «участник × комната»: просмотр, редактирование, админ-права).

Настройки серверов, права и сессия сохраняются локально; «Сброс» в панели серверов
возвращает значения по умолчанию.
